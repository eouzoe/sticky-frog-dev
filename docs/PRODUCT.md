# 產品方向與路線（2026-10-30）

這份是避免遺忘用的紀錄：定位、做決定的原則、第一版範圍、以及明確「不在第一版」但之後要做的東西。
技術問題清單在 REVIEW-2026-10-30.md。

## 定位

- CrazyGames 上的小遊戲，現階段是**驗證市場**：有數據證明會受歡迎之後，才考慮獨占、重構玩法與畫風、換平台、加大投入。
- 核心資產只有一個：**一直盪的手感、一局接一局、沒事就想玩一下**。
- 美術往小遊戲方向走：乾淨、清楚、不卡。不追精緻，不佔效能，但也不是粗製濫造。
- 之後靠短影音（AI 批量剪輯精華片段、同模板換配樂換素材大量投放）引流回來。

## 做決定時用的原則

1. **盪的過程中永遠不能卡一下。** 熱迴圈零配置、遊玩中不寫 DOM、音效不能一幀建幾十個節點、SDK 不能擋主執行緒。一次 100 ms 的停頓就毀掉那一盪。
2. **流程不打斷。** 落地那一下的停頓是唯一的節拍。關與關之間沒有按鈕、沒有廣告、沒有選單。
3. **預算給玩法層。** 鉤子、荷葉、危險物、角色、舌頭、回饋優先；背景只負責襯托，而且不動用資源。
4. **每個改動都要便宜。** 模組小、邊界清楚、模擬與計分有測試鎖住行為，改完自己能驗證，不用等人試玩才知道壞了。
5. **一切可量。** 漏斗事件是功能的一部分，不是事後加的。
6. **一切可重播。** 一局＝種子＋輸入序列。這是回放、導出、批量剪輯的共同地基。

## 第一版：遊戲本體

目標：一個使用者試玩後覺得「完全可行」的版本。本地完成、jj 原子提交排好；**在使用者說可以之前不推送、不開 PR**。

- 低階手機 60 fps 不卡頓：三層視差背景、平塗水面與漸層天空、開機拆成核心與延後模組、永不等 SDK、零配置熱迴圈、音效預先算成緩衝。
- 止血：存檔合併（版本號、時間戳、逐欄合併）、無盡模式結算、語言選擇存檔、WebGL context lost、世界圖集洩漏。
- 流程：關卡結束沒有任何按鈕；顯示星星與金幣後無條件進下一關；顯示要短而刻意，分「豪爽」與「可惜再來」兩套節拍，時間固定；主線與無盡統一成一個流。
- 金幣：遊戲中有難度地取得；當下噴出、短暫懸空、飛到左上角計數器，數字在到達那一刻才跳。減少獲取量讓它珍貴。
- 回放地基：錄製格式進存檔、可決定性重播、遊戲內能看回放。導出不在第一版。
- 主題地基：主題定義成資料包（角色零件圖集、舌頭、拖尾、旋轉與落地動畫、音效組、可選地圖層）；旋轉貓做成第一個完整主題。
- 量測：局長、每局關數、重試率、無盡距離分布、流失點、「想買但不夠」的瞬間。
- 專案整潔：過期測試與 devenv 設定清掉、文件更新。

### 第一版就要留好的接口（之後補會很貴）

- 錄製：種子＋輸入序列進存檔格式；輸入要帶物理步編號，不帶牆鐘時間。
- 渲染：能用固定時步、在離屏畫布、以任意解析度重畫；鏡頭能被腳本控制。
- 主題：資料包的載入路徑（圖集＋設定＋音效組），引擎不認識任何特定主題。
- 遙測：事件格式固定，精彩局（種子＋輸入，幾百位元組）能上傳。

### 待使用者確認的預設

- 六個世界共用背景結構，只換色和一兩層特色元素，危險物照舊。這是最便宜的做法，差異會比現在小一點。
- 導出影片放第二階段。

## 第二階段之後（記下來，不在第一版）

### 回放與導出

- 導出格式：瀏覽器內用 WebCodecs 編 H.264，加一個約 20 KB 的 MP4 封裝器，直接產出標準 MP4，不需轉換，各平台直接吃。「支援所有主流格式」實務上就是 MP4。
- 預設組：TikTok／Shorts 9:16（1080×1920，長度上限）、YouTube 16:9、方形；各自的安全邊距。畫質分級（解析度、位元率）。
- 長度：片段＝回放裡的一段時間範圍，不是整局。
- 手機上用系統分享把檔案丟進 TikTok 等 App；直接 API 上傳要申請開發者帳號，再說。
- 聲音：音效是程序合成，導出時用離線音訊環境跟著重播算，逐幀對齊。配樂在批量工具那邊加。

### 內建剪輯

可行，而且便宜，因為「片段」不是影片檔，是「回放加參數」，剪輯等於改參數再渲染一次。能做的：

- 選時間範圍、標慢動作點、換主題、換比例裁切、換鏡頭距離。
- 不做的：多軌時間軸、轉場、字幕特效。那是剪輯軟體的事，交給批量工具。

### 批量剪輯工具（自己做，離線）

- 無頭瀏覽器跑同一個重播引擎逐幀輸出，ffmpeg 合成。基礎設施跟烘焙工具是同一套。
- 模板：開場、慢動作點、結尾導流畫面；配樂庫輪換；主題輪換；比例輪換。同一局換十套主題和十首配樂就是一百支影片。
- 來源：遙測上傳的真實高分局，或自動玩家跑出來的局。
- 輸出：批量 MP4 加中繼資料（哪一局、哪個主題、哪首配樂），投放後對照反應。

### 主題與地圖（2026-10-30 使用者定案，可以開始實作；先做旋轉貓與它的組合包）

主題＝一整套：角色本體、移動特效、音效組、舌頭、道具替換、系列關卡。旋轉貓：貓本體、毛線球舌頭、毛線拖尾、oiia 音效組、蒼蠅→小魚乾、起點樹樁→貓跳台（或貓窩）、貓系列關卡。
同樣邏輯：人猿＝藤蔓舌頭＋叢林關卡；蛛絲緊身衣＝蛛絲舌頭＋都市地圖。形象不用名字，不處理版權問題。

**資料包（引擎不認識任何特定主題）**
- `skin`：角色零件圖集或照片；`tongue`／`trail`：舌頭與拖尾樣式；`sfx`：音效組（主題覆寫 `play(name)` 的對應表，沒覆寫的用預設）
- `props`：道具替換表，例如 `{ fly: 'fish', start: 'catTower', pad: 'cushion' }`；沒列的用該世界的預設道具
- `levels`：系列關卡（用現有產生器＋主題道具，難度對應中段），擁有主題才解鎖；之後可接「看廣告解鎖」
- `price`：`{ bundle, items: { skin, tongue, trail, levels } }`，單買總和高於組合包；`sale?: { until, bundle }` 限時特價（先用本機時間，之後遙測伺服器給時間防作弊）

**購買與裝配**
- 買組合包：全部進 `owned`，並一鍵套用整套（`save.theme = 'cat'`：道具替換與音效組跟著主題；skin／tongue／trail 仍可各自換，混搭也行）
- 單買：各自進 `owned`、各自裝配；集齊後商店出現「套用整套」
- 廣告購買：等有廣告再接，介面先留位置

**系列關卡**
- 選關頁多一個主題分頁；星數、金幣同一套經濟；關卡內的道具、起點、蒼蠅全換成主題版
- 第一版只做貓一套走通整條路（買、裝、關卡、數據），驗證的是機制不是目錄
- **系列關卡是全新世界**（2026-10-30 使用者）：背景、主題、氛圍整個換，不是既有世界換道具；關卡內容要特別設計（手工排），不走隨機產生。主題音效不另做

**要做的素材（貓）**：小魚乾、貓跳台或貓窩、軟墊荷葉；毛線拖尾；音效組（黏住喵一聲、吃魚乾鈴鐺、落地）。畫法跟下面的美術方向一起決定。

**死亡特效要全年齡（2026-10-30 使用者，已改）**：撞到障礙物原本噴身體色碎片＋紅色，改成一團柔軟的白雲慢慢散開、幾顆小星、淡淡一閃；簡單、溫和，不另做動畫。落水的水花本來就溫和，不動。

**障礙物要全年齡（2026-10-30 使用者，已改：石頭、蝴蝶，向量佔位）**：尖刺與鋸片不適合，換成石頭、蝴蝶這類東西——固定障礙（原尖刺）→ 石頭／岩塊，移動障礙（原鋸片）→ 蝴蝶群、蜜蜂這類會動但不血腥的；死法文字跟著改。障礙物進主題的道具替換表（`props.spike`、`props.saw`），主題可以整套換。模擬層不動（還是圓形碰撞），只換圖與名字；跟美術方向一起做。

**霓虹城的賽博龐克元素（使用者私心，先不做）**：想在霓虹城加更多那種氛圍（霓虹雨夜、義體、街頭廣告牌）。網頁小遊戲階段不合適，等切換平台後再考慮；到時候一樣用氛圍與元素，不用任何名字。

### 定位改變（2026-10-30 晚，使用者定案）

看過獨立遊戲參考板（Alto's Odyssey、OlliOlli World、Pikuniku、Donut County、Untitled Goose Game、Night in the Woods、GRIS、A Short Hike、Chicory）之後：

- **美術全面改成 Alto's Odyssey 的做法**：遠近全是剪影層＋漸層天空，天氣與時間用顏色做；**角色也做成剪影**，完全符合 Alto 的感覺。Night in the Woods 還行、GRIS 優秀但不一定適合、Pikuniku 太商業不夠精緻。
- **旋轉貓的照片刻意突兀，這正是賣點**，保留，不改成剪影。
- **調性整個換**：從 CrazyGames 那種魔性、殺時間、迷因／借鑑 IP 的網頁小遊戲，變成講究故事、感受、流動感的精緻獨立小遊戲。玩法不變、概念不變（根源就是一個物體、一根線、盪）。**這個方向不適合 CrazyGames**，原本那個版本才適合。
- **範圍跟著拉長**：整體流程拉長；地圖上下拉寬、左右拉長、加更多元素。故事與章節都是可能：主角就算還是青蛙，寫一個「小青蛙找媽媽」也行；或換別的方式、不同角色的章節、照主題分模式。都還沒定。
- **做法**：還沒改美術的版本定檔（jj 書籤 `mvp-crazygames`，之後不動，它就是 CrazyGames 那條線的成品）；新美術在另一個資料夾 `sticky-frog-indie` 開始嘗試，先做出來看。

### 美術方向（已定：Alto 式剪影；下面是定案前的候選，留做紀錄）

目標兩個：效能與載入更強、更好看更可愛（休閒小遊戲的精緻感，不要粗製濫造）。候選：
- **向量卡通（跟現在的介面同一種語言：軟膠漸層、粗描邊）**：素材是 SVG，離線用同一套烘焙工具光柵成圖集；下載極小、任何 DPR 都清楚、換色就能出主題變體；AI 或人工都容易產。目前最傾向。
- 保留烘焙 3D 但重打光（環境光遮蔽、柔陰影）：執行期零成本，但風格上限就是現在這樣。
- 手繪：最好看，產能最差，主題擴充成本最高。
決定之後背景層的構圖設計、主題素材、主角零件一起換，不要分批。

### 經濟

- 金幣獲取量低、入帳要有感；每一次「想買但不夠」都記錄，作為定價依據。

### 社交（可能不需要）

- 用戶主頁、好友、排行。CrazyGames 有平台排行可以先用，自己做的放最後。

### 短影音營銷

- 官方帳號、批量投放、模板不斷切換配樂與素材，看反應，引流回 CrazyGames。
