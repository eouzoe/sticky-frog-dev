# Batch A1 — Save reconciliation (draft issue + PR list)

Base: `origin/main` (upstream, JavaScript). Integration branch: `batch/A1`. Language of issue and PRs: British English, facts only.

## Issue (draft)

**Problem.** `main.js` boots only after the CrazyGames SDK answers (up to 2.4 s on the web build, 8 s on CrazyGames). When the SDK arrives late, the cloud save replaces the local save unconditionally; if the cloud copy is empty the local progress is discarded. After a level has started, every later write pushes the local copy over the cloud one. The save has no version field and no timestamp, so neither side can tell which copy is newer. Source: `docs/REVIEW-2026-10-30.md` §2 (reproduced with `tools/perf/fixcheck.mjs` in the rewritten tree; the same code path exists in `src/main.js` and `src/cg.js` upstream).

**Change.** Add `v` and `updatedAt` to the save; add `mergeSave(a, b, levelCount)` that takes the union/maximum of achievement-type fields (unlocked, stars, best scores, feats, leaderboard, owned items, endless records) and the newer copy for state-type fields (coins, current level, equipped items, settings, language); boot from the local save immediately and merge when the SDK reports ready; `cg.setItem` always mirrors to `localStorage`; `cg.getItem(key, from)` can read a specific source.

**Non-goals.** No renderer or UI change. No change to the save key or to how stars/levels are recorded.

**Verification.** `node tests/save-check.mjs` (new merge cases: union of achievements, newer-wins for state, order independence, empty cloud keeps local, legacy save without timestamp treated as oldest). Manual: load with SDK blocked, play one level, unblock — progress kept.

**Compatibility.** Legacy saves (no `v`/`updatedAt`) normalise to `updatedAt = 0` and are treated as the oldest copy. Save key unchanged.
