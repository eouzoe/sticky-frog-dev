# Batch A4 — Settle an endless run at the moment of death (draft issue + PR list)

Base: `batch/A1` head (linear chain A0 → A1 → A4 on the `exp` branch; the diff against `origin/main` is one file). Integration branch: `batch/A4`. Language: British English, facts only.

## Issue (draft)

**Problem.** `endlessOver()` records the run (best distance, run count, local leaderboard, platform score, telemetry, save) only when the over screen opens, 0.8 s after death. Restarting (R) or returning to the menu inside that window resets the timer, and the run is never recorded. Source: `docs/REVIEW-2026-10-30.md` §2; reproduced with the dev hooks (die in endless, press R within 0.8 s, `endlessBest` unchanged).

**Change.** The recording part becomes `recordEndless()`, called from the die handler at the moment of death. `endlessOver()` only shows `G.lastResult`. Timing of the over screen, ads and the double-coins offer are unchanged.

**Non-goals.** No change to the flow redo in the rewritten tree (batch C2); this is the smallest fix on the upstream code.

**Verification.** `node --check src/main.js`; `vite build`; manual: die in endless, press R immediately, `endlessBest` and the local leaderboard update.

1. `main.js` — `recordEndless()` split out of `endlessOver()`, called in the die handler; `G.lastResult` gains `newBest` so the over screen can still show it. kind:design, ~10 min.
